# 安全审计报告 —— 基于国密 SM9 的端到端加密文档投递系统

审计日期：2026-09-19
审计方式：全量只读代码审计（3 个并行审计代理 + 主审计人工复核），覆盖 backend-app（135 个 Java 文件中的全部 main 源码）、kgc-service（26 个源文件）、frontend/src（全部 29 个文件 + index.html/vite.config.js/dist 产物）、deploy/ 脚本、database/ 初始化脚本、poc-crypto/。所有关键代码行均已人工复核文件与行号。未修改任何代码。审计时服务未运行，动态探测项已标注为「待验证」。

严重度口径：高 = 真实部署环境即构成实质危害（本机回环演示边界内多数可降级）；中 = 纵深防御缺口或特定条件可利用；低 = 加固建议/标准符合性/资源管理。

## 一、高危发现（3 条）

### H-1 生产档凭据 fail-open：KGC 令牌、主密钥口令、MinIO、数据库全部带仓库内弱默认值
位置：backend-app/src/main/resources/application.yml:43-44,51；kgc-service/src/main/resources/application.yml:31,34；application-prod.yml（均未覆盖）；KgcClient.java:34

- KGC 服务令牌默认值 `dev-kgc-token-change-me`，两侧硬编码且一致；KGC 主密钥落盘加密口令默认值 `dev-kgc-master-passphrase-change-me`；MinIO 默认 `minioadmin/minioadmin`；prod MySQL 默认 `root/root`。
- 全部支持环境变量覆盖，但 **prod 档不设环境变量时静默沿用弱默认值，无任何启动告警或拒绝**。
- 后果链：拿到 KGC 令牌 → 为任意已登记身份签发私钥（issue/reissue 共用同一令牌）；拿到主密钥口令 + 密钥文件 → 解出 SM9 主私钥 ke，击穿整个体系（所有用户所有密文）。
- 建议：prod 档去掉默认值（缺失即启动失败）；启动时检测到占位默认值打印 ERROR；密钥走密钥管理服务。答辩前最低限度：在 deploy/README 和启动脚本中强制要求设置环境变量并校验。

### H-2 浏览器端 SM9 私钥明文存 IndexedDB，XSS 可一键窃取；IBE 私钥确定性导致无法作废
位置：frontend/src/store/idb.js:21-29；KeyInit.vue:27-30；Decrypt.vue:35；kgc-service/.../KgcIssueService.java:133-134

- KGC 签发时私钥 de 直接 Base64（无口令包装），前端原样存 IndexedDB（store `securedoc/sm9keys`），解密时直接取用，全程无解锁步骤。
- XSS 注入的脚本与站点同源，同源策略对其无效，`indexedDB.open('securedoc')` 几行代码即可外带私钥。
- 更严重的是 IBE 固有属性：同一身份重签出的私钥完全一致（KeyInit.vue:49 明示），私钥泄露后**无法通过重签发作废**，只能换身份；攻击者拿到私钥后可解该身份的全部历史密文，无前向保密。
- 缓解：口令派生 KEK（PBKDF2 + AES-GCM）包裹后存储、每次解密要求输口令（把「静置窃取」变为「解锁窗口窃取」）；根本防线是防 XSS（严格 CSP、改造 gmssl 加载方式去掉 new Function）。论文安全分析须写明此威胁模型边界。

### H-3 演示凭据 + 默认监听全网卡 + H2 控制台空密码：局域网内 admin 直接失守
位置：database/init_data.sql:22-27；frontend/src/pages/Login.vue:14-18；SecurityConfig.java:68；application-dev.yml:19-22；deploy/README.md:86

- 全部演示账号（含 SYS_ADMIN 的 admin、SECURITY_AUDITOR 的 auditor）口令统一 `Demo@123`，登录页明文展示并一键填充；Spring Boot 默认监听 0.0.0.0。
- dev 档 H2 控制台 `/h2-console/**` 在 SecurityConfig 中 permitAll，数据库 sa/空密码：任何能访问 8080 的人可直读全库，甚至 UPDATE users/user_roles 给自己提权 SYS_ADMIN。KGC（8081）同样开启 H2 console 且不在令牌过滤器 PROTECTED 集合内，可篡改 user_keys 身份绑定。
- MinIO 控制台按 README 命令绑全网卡 + 默认凭据。
- 本机回环演示（不连局域网）为设计取舍；一旦接入任何共享网络立即构成真实漏洞。建议：演示期间确认仅本机访问或全部绑定 127.0.0.1。

## 二、中危发现（7 条）

### M-1 CSRF 全局关闭；dev 档会话 Cookie 无 HttpOnly/SameSite
位置：SecurityConfig.java:63；application.yml（无 cookie 配置）；仅 application-prod.yml:28-31 设 http-only+lax

- CSRF 在 dev/prod 均关闭（SEC-1 ADR 已决策）。prod 靠 SameSite=Lax 缓解（现代浏览器有效），但 dev 档 JSESSIONID 连 HttpOnly 都没有（Tomcat 默认不带），XSS 可直接偷会话 Cookie。无 Secure 标志（本地 HTTP 所致）。
- 建议：把 http-only:true + same-site:lax 提升到 application.yml 基线，dev/prod 共用；HTTPS 部署加 secure:true。

### M-2 KGC 绑定 0.0.0.0 + 明文 HTTP，无 TLS/IP 白名单
位置：kgc-service/src/main/resources/application.yml:5-6

- 只配了 port 8081 无 server.address → 监听全部网卡；令牌在请求头、128 字节私钥包在响应体均为明文，同网段可嗅探。
- 建议：prod 绑定 127.0.0.1（或专用内网 + 防火墙白名单）；生产 mTLS（设计文档 §2.6 已有演进方向）。

### M-3 KGC 令牌校验无速率限制，令牌不绑定调用方
位置：kgc-service/.../KgcTokenFilter.java:45-55；KgcIssueService.java:144

- 401 不计数、不延迟、不限流 → 弱令牌可在线枚举爆破；过滤器只验证令牌对不对，不区分调用方，operatorId 取自请求体自报值。
- 建议：401 指数退避 + 来源限流；令牌按调用方签发并绑定操作范围。

### M-4 上传分块 body 先整体读入内存再校验大小；无用户存储配额
位置：FileController.java:63（@RequestBody byte[]）；FileUploadService.java:123（校验在读取之后）；application.yml:7-8（max-swallow-size:-1）

- 任意登录用户可向 `/api/files/{fileId}/chunks/{i}` 发送超大二进制 body：Servlet 层无大小上限，body 完整读入内存后才在 Service 里被 maxChunkSize 拒绝 → 单请求即可打爆堆内存（OOM）。此外无单用户存储总量配额，可反复合法上传 8MB 块耗尽磁盘。
- 建议：Servlet/Filter 层先按 Content-Length 拒绝（如 >8MB 直接 413）；增加每用户总配额或全局限额。

### M-5 deviceFingerprint 全信客户端，无绑定语义、无长度校验
位置：kgc-service/.../KgcIssueService.java:151

- fingerprint 原样入库（VARCHAR(255)），非空即置 deviceBound=true，从不比对任何已存值；超长（>255 字节）会 insert 报错返 500。该字段目前仅是审计装饰。
- 建议：加格式/长度校验；论文如实说明 deviceBound 仅为审计字段。

### M-6 无 CSP；gmssl 以 new Function 加载，未来任一 XSS 即灾难级
位置：frontend/index.html:3-7；crypto/gmssl.js（CRYPTO-1 已挂账）

- 当前代码层无任何 XSS sink（29 个文件 v-html/innerHTML/document.write 零命中，Vue 插值转义），但浏览器内存中持有私钥与解密明文，纵深防御为零；设置严格 CSP 又会拦 new Function。
- 建议：先改造 vendored gmssl 为严格 ESM 加载，再加 CSP（default-src 'self'; object-src 'none'; frame-ancestors 'none'）。

### M-7 KGC 库审计无 SM3 哈希链，库内审计可被改库者静默篡改
位置：kgc-service/.../entity/AuditLog.java:31-32（字段预留但从未填充）；KgcAuditService.java:21-30

- backend 的 audit_logs 有哈希链 + verifyChain 校验，但 KGC 独立库的 KGC_ISSUE/KGC_REISSUE/KGC_REGISTER 记录与 kgc_private_key_issues 表均无防篡改，能改库者（如 H-3 中的 H2 console）可抹掉签发痕迹。
- 建议：KGC 库启用同款哈希链；论文如实说明。

## 四、正面结论（做得对的部分，答辩可用）

- SQL 注入：全部 Mapper 参数化，无 ${} 拼接，无 MyBatis XML；LIMIT 拼接为钳制后的 long 值。
- 水平越权（IDOR）：未发现。上传/complete 校验发送人，下载/密钥信封校验接收人（requireRecipient + 安全事件记录），fileId 为服务端 UUID，chunkIndex 越界校验。
- 垂直越权：Admin/Audit/Role 接口全部 @PreAuthorize；/api/keys/init 无 userId 入参，结构上只能签发会话用户自身（ADR-KGC代理 落实）；管理员禁止自改角色/状态防自降权自锁。
- 认证：BCrypt 存储；登录会话固定防护（invalidate 后重建）；登出销毁会话；SecurityUser.passwordHash transient 不入会话；账号锁定 + IP 限流双防线（含并发撞 unique 的 THROTTLE-1 加固）。
- 主密钥：SecureRandom 生成；PBKDF2-HMAC-SHA256(210k) + AES-256-GCM 密文落盘（实测确认 magic SM9KGCv1，非明文）；data/ 已 gitignore；全库日志无密钥材料输出。
- 令牌校验常量时间比较（MessageDigest.isEqual）。
- 私钥包后端仅中转不落库；KGC 令牌不出浏览器；dist 产物无秘密（KGC 令牌/MinIO 凭据均未进前端 bundle）。
- 前端：无任何 XSS sink；随机数全部 crypto.getRandomValues（含 vendor 库零随机源的外部注入设计）；每块独立随机 IV；DEK 16B；token 不落 localStorage；SM9 实现与 GM/T 0044 官方测试向量一致，负例（错私钥/篡改）齐全；上游 SM3 多分块 bug 已修复并有注释。
- 路径穿越防护到位（normalize + startsWith(root)）；全局异常不回堆栈；下载侧 SM3 重算防对象存储篡改；上传完整性 FILE-2（index 连续性）已修复。
