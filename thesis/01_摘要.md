# 摘要

## 摘要

企业内部文档在流转过程中面临外部窃取、内部越权和存储侧泄露等风险，传统“传输层加密+服务端存储加密”方案仍可能使服务端获得明文。针对该问题，本文设计并实现了一个基于国密 SM9 标识密码的端到端加密文档投递系统。系统采用“浏览器加密端—盲存储应用服务器—密钥生成中心（KGC）”分域架构：浏览器使用 SM4-CBC 分块加密文件，以 SM3 校验密文完整性，并按接收人 SM9 身份分别封装文件密钥，实现“一份密文、多人接收”；业务数据库和对象存储仅持久化密文、加密元数据与密钥信封，不持久化明文、文件密钥和用户身份私钥；KGC 负责确定性私钥提取，主私钥经 PBKDF2-HMAC-SHA256 与 AES-256-GCM 加密落盘。系统还实现了 SM3 审计哈希链、方法级访问控制和七类安全事件记录。复测结果表明，业务后端与 KGC 的 128 项单元及集成测试全部通过，五组端到端脚本共 61 个检查点全部通过；SM3、SM4 和 SM9 关键运算通过标准或官方示例验证。相同密码模块三次基准的热态 SM9 封装平均耗时约 30.9 ms，SM4 吞吐率约 13.44 MB/s；50 MB 文件在本机测试中完成加密与摘要用时 5.7 s，下载、校验与解密用时 8.3 s。结果说明，在明确 KGC 与应用控制面为可信边界的前提下，国密标识密码用于浏览器侧加密文档投递具有工程可行性。

**关键词**：SM9 标识密码；端到端加密；混合加密；盲存储；哈希链审计

## Abstract

Enterprise documents face risks including external theft, internal unauthorized access, and storage-side leakage during delivery. Conventional schemes combining transport encryption with server-side storage encryption may still expose plaintext to the server. To address this problem, this thesis designs and implements an end-to-end encrypted document delivery system based on the Chinese SM9 identity-based cryptographic algorithm. The system separates a browser-side encryption client, a blind-storage application server, and a Key Generation Center (KGC). The browser encrypts file chunks with SM4-CBC, checks ciphertext integrity with SM3, and encapsulates the file key separately for each recipient identity with SM9, thereby supporting one ciphertext for multiple recipients. The business database and object storage persist only ciphertext, encrypted metadata, and key envelopes; they do not persist plaintext, file keys, or user identity private keys. The KGC performs deterministic private-key extraction, while its master secret is sealed on disk using PBKDF2-HMAC-SHA256 and AES-256-GCM. The system also implements an SM3 audit hash chain, method-level access control, and recording for seven categories of security events. In the repeated evaluation, all 128 unit and integration tests for the application server and KGC passed, as did 61 checks in five end-to-end suites. Key SM3, SM4, and SM9 operations were validated against standards or official examples. Across three benchmark runs of the same cryptographic module, warm SM9 encapsulation averaged approximately 30.9 ms and SM4 throughput averaged approximately 13.44 MB/s. For a 50 MB file, encryption and hashing took 5.7 s, while download, verification, and decryption took 8.3 s on the test machine. The results demonstrate the engineering feasibility of browser-side encrypted document delivery with Chinese identity-based cryptography under an explicitly trusted KGC and application control-plane boundary.

**Key words**: SM9 identity-based cryptography; end-to-end encryption; hybrid encryption; blind storage; hash-chain audit
