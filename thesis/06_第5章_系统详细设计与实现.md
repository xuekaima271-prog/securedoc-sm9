# 5 系统详细设计与实现

## 5.1 国密加密模块

### 5.1.1 浏览器端混合加密实现

浏览器端加密模块以纯 JavaScript 实现 SM3、SM4 与 SM9 三种算法，其中 SM9（含 R-ate 双线性对）的基础运算移植自 GmSSL-JS[17]。发送端封装与接收端解封的对应关系如图5.1所示。

![图 5.1 浏览器端混合加密与解密流程](images/fig5-1-crypto-flow.png)

文件加密（封装）流程实现为：

（1）以密码学安全随机数生成 128 比特 SM4 文件密钥 DEK；

（2）文件按自适应大小分块：不超过 16 MB 的文件使用 256 KiB 分块，大于 16 MB 的文件使用 4 MiB 分块；每块生成独立随机 IV，执行 SM4-CBC 加密并计算密文的 SM3 摘要；

（3）文件名、MIME 类型与用户备注组成元数据 JSON，同样以 DEK 执行 SM4 加密；

（4）对每位接收人的 SM9 身份标识执行式(2.4)~式(2.6)的密钥封装，将 DEK 包装为该接收人专属的密钥信封。当前信封由 64 B 的 $C_1$、32 B 的 $C_3$ 和 16 B 的 $C_2$ 组成，总长 112 B。

解密（解封）流程执行相反操作：SM9 解封信封得到 DEK，逐块比对 SM3 摘要后以对应 IV 执行 SM4-CBC 解密，最终拼装还原原始文件。SM3 摘要用于损坏检测而非带密钥认证；恶意服务端同步替换密文与摘要的风险在结论中列为后续改进项。

### 5.1.2 GmSSL-JS缺陷修复

在“真服务签发的私钥 ↔ 浏览器加解密”端到端互通的负例测试（正确身份串搭配错误私钥应当解密失败）中，发现 GmSSL-JS 存在两处相互掩盖的缺陷：

（1）**SM3 多分块缺陷**：压缩函数的分块循环未推进读取偏移，长度超过两个完整分组的消息只有首块与缓冲尾块参与运算，中间分组被忽略。由于 SM9 密钥派生的输入 $C_1(64\text{B}) \parallel w(384\text{B}) \parallel ID$ 中配对值 $w$ 恰好落在被忽略的中间分组，派生出的对称密钥与接收人私钥完全无关——任何知道（公开的）身份串的人都能“解密”，机密性实际被破坏。修复方法是在每个分组处理后将偏移推进 64 字节。

（2）**点乘基点坐标缺陷**：封装计算 $C_1=[r]Q_B$ 时，$Q_B$ 是点加运算输出的 Jacobian 坐标，而点乘实现要求仿射坐标基点，导致 $C_1$ 计算错误。修复方法是在点乘前将 $Q_B$ 归一化为仿射坐标。

定位采用固定向量二分法（对 SM3 修改不同位置的输入观察摘要是否变化）与双线性对、幂运算、点乘的逐环节隔离探针。修复后，强负例测试（正确身份+错误私钥必须失败）、Java 与 JavaScript 互通测试全部真实通过，SM9 解密真正与私钥绑定。这一过程也说明：密码实现的正确性验证必须包含负例，仅有正例通过可能掩盖机密性缺陷。

### 5.1.3 WebWorker与大文件处理

加解密运算移入 WebWorker 后台线程执行：主线程在消息边界将文件 ArrayBuffer 以所有权转移方式交给 Worker，Worker 逐块回报进度，主线程渲染进度条；若 Worker 创建失败则回退到主线程执行。进入 Worker 后，当前实现仍会把 ArrayBuffer 转成 JavaScript 数组并在上传前收集全部密文块，因此属于后台分块处理，而非严格的端到端流式零拷贝。解密侧还原文件时，代码避免将大字节数组展开为函数参数，改用 Blob 分片拼装，已通过 50 MB 文件场景测试。

## 5.2 KGC密钥中心

### 5.2.1 主密钥安全存储

KGC 启动时执行“加载或生成”策略：首次启动以 SecureRandom 生成主私钥 $ke$，加密封存至磁盘；再次启动则解封恢复。口令经 PBKDF2WithHmacSHA256（210 000 次迭代）派生 256 比特密钥加密密钥（KEK），再以 AES-256-GCM 加密主私钥；随机盐（16 B）和随机 nonce（12 B）随文件保存，GCM 认证标签用于检测错误口令或密文篡改。PBKDF2 的规范依据见 RFC 8018[15]。开发配置为便于演示保留了默认口令，生产部署必须移除默认值并强制通过环境变量注入，同时分别备份主密钥文件和口令，否则历史私钥与密文将无法恢复。

私钥签发与重签发流程如图5.2所示。签发包含三重校验：身份串格式必须符合 `user:{租户}:{用户ID}:{邮箱}` 规范；用户必须存在；请求身份必须与数据库登记的身份一致，不一致即拒绝（IDENTITY_MISMATCH）。签发成功后写入签发流水（区分 FIRST/REISSUE 类型）、推进用户密钥状态机（UNINITIALIZED→ISSUED→REISSUED），并记录普通审计日志。KGC 流水当前未接入业务 SM3 哈希链。

![图 5.2 KGC私钥签发与重签发流程](images/fig5-2-key-issue-flow.png)

由式(2.3)可知，SM9 用户私钥 $de_B=[t_2]P_2$ 由主私钥和身份标识确定，不含随机成分。因此在主密钥不变时，同一身份任意次提取的私钥逐字节一致。端到端脚本验证了首发与重签发私钥的字节一致性，并用重签发私钥完成新文件解密；脚本尚未直接保存一份签发前的历史文件再执行跨设备恢复，故历史文件恢复主要由私钥等同性和密码流程推导支持。

签发类接口以服务令牌（X-KGC-Token）鉴权，令牌比较采用常量时间算法。浏览器不直接访问 KGC，签发请求经应用服务器代理转发，KGC 网络边界可收缩至仅允许应用服务器访问。但静态令牌使完全失陷的应用服务器能够请求已登记身份的私钥，因此生产环境还需 mTLS、短期凭据、用途约束和异常签发审批。

## 5.3 文件盲存储服务

### 5.3.1 分块上传与下载协议

上传采用“初始化—传块—完成”三段协议：初始化请求携带加密元数据、全部接收人的密钥信封与分块清单，服务端创建 INIT 状态的投递记录；随后逐块上传密文，每块携带序号、IV 与浏览器计算的 SM3 摘要，服务端复算摘要，失配立即拒绝该块；全部分块就位后提交完成，记录置为 AVAILABLE，接收方才可见。下载方向服务端先复算存储对象摘要，若与数据库登记值不一致则拒绝并记录 CHUNK_TAMPER_DETECTED；正常响应在头部返回分块序号、摘要与 IV，浏览器再次比对后解密。分块大小设有上限，超限拒绝并记录 MEDIUM 级 OVERSIZED_CHUNK。当前下载第一个分块时即更新“已下载”状态，而不是在全部分块成功后更新，这是状态语义上的已知不足。

### 5.3.2 存储抽象与条件装配

密文分块的物理存储抽象为统一的 Storage 接口，提供本地文件系统与 MinIO 对象存储两个实现，经 Spring 条件装配按配置项 `storage.type=local|minio` 选择，业务代码无需改变即可切换。本次可复现回归使用本地存储；MinIO 实现、配置与单元测试已经存在，但本次论文交付未重新保留一套 MinIO 活体端到端日志，因此不把“两种实现本次均通过完整场景”作为实验结论。

### 5.3.3 跨服务一致性

创建用户涉及应用库写入与 KGC 身份登记两个跨服务步骤，采用尽力补偿流程：先在本地事务提交用户与密钥占位记录，再调用 KGC 登记身份；若调用明确失败，则按外键逆序删除刚创建的本地记录并返回原因。该流程避免在数据库事务内等待远程调用，降低共库场景的锁等待风险，但不是严格 Saga：若 KGC 已提交而响应丢失，本地补偿仍可能留下孤立的 KGC 身份，需要幂等重试或人工清理。

## 5.4 用户权限与审计安全事件

### 5.4.1 RBAC与管理功能

系统在 Spring Security 上启用方法级授权：管理接口仅 SYS_ADMIN 可调用，审计与安全事件接口仅 SECURITY_AUDITOR 可调用；未登录与越权分别由统一入口点返回 401/403 JSON。管理员可创建用户、启用或停用账号并调整角色，接口禁止管理员修改自身账号。文件与密钥接口目前只要求登录和资源归属，并未额外限定 EMPLOYEE 角色。

### 5.4.2 审计哈希链实现

审计服务按式(4.1)维护哈希链。单实例内以互斥锁串行化“读链尾—计算—插入”三步，降低并发写入造成链分叉的可能；记录的部分字段序列化后参与哈希。链校验接口按主键升序重放，发现当前哈希或前向链接不一致时返回断点并记录 AUDIT_CHAIN_BROKEN。当前哈希未覆盖 userAgent，也没有把链头或周期锚点发布到外部可信介质，因而不能检测链尾或整表删除；多实例部署还需改用数据库锁或集中序列。审计写入采用尽力而为策略，审计故障不阻断业务主流程。

### 5.4.3 安全事件埋点

七类安全事件（表 4.3）的埋点分布于登录限流服务（暴破锁定、IP 限流）、安全过滤器与全局异常处理器（越权双埋点）、文件下载服务（非接收人访问）、上传下载服务（篡改、超大块）与审计链校验（链断裂），每条事件带有类型、级别、主体、资源与描述，审计员可在专门页面按级别检索。安全事件面向“攻击面”告警，与面向“操作面”的审计日志形成互补。

## 5.5 前端交互实现

前端基于 Vue 3 与 Vite 构建，未引入第三方 UI 组件库，以自建轻量设计系统保持界面一致。发送页支持文件拖拽选择，接收人以头像卡片多选；上传与下载过程显示逐块进度与阶段提示。备注随元数据加密，接收页可在浏览器内预览解密后的文本与图片。密钥初始化和重签发采用向导式操作，审计日志、安全事件与 KGC 签发记录提供独立页面。用户私钥当前以 Base64 包形式保存在 IndexedDB；所谓“设备指纹”只用于记录浏览器环境信息，不构成密码学设备绑定，生产环境宜结合 WebAuthn、系统密钥库或用户口令二次加密。

## 5.6 本章小结

本章给出五个核心模块的实现：浏览器国密混合加密模块完成 SM9 移植并修复两处缺陷，WebWorker 将主要运算移出主线程；KGC 实现主密钥加密落盘与确定性私钥提取；盲存储服务实现三段分块协议、摘要比对和可切换存储抽象；权限审计模块实现方法级 RBAC、具有限定检测能力的 SM3 哈希链与七类安全事件；前端以向导式交互降低使用门槛。实现边界与剩余风险均将在第 6 章测试和结论中进一步说明。
