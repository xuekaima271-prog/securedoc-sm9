# 3 系统需求分析

## 3.1 功能需求

系统面向企业内部文档投递场景，主要区分三类具有差异化权限的角色：普通员工（EMPLOYEE）、系统管理员（SYS_ADMIN）与安全审计员（SECURITY_AUDITOR）。角色与核心用例的关系如图3.1所示。当前实现中，文件与密钥接口以“已认证”为基本条件，并未额外强制 EMPLOYEE 角色，因此管理员和审计员账号在满足资源授权条件时也可调用相关用户接口；表3.1按实际授权边界表述。

![图 3.1 系统角色与核心用例](images/fig3-1-use-cases.png)

各角色的功能需求如表3.1所示。

表 3.1 系统功能需求清单

| 编号 | 功能 | 角色 | 说明 |
|---|---|---|---|
| F1 | 登录认证 | 全体 | 用户名口令登录，口令仅以 BCrypt 哈希存储；失败次数超限锁定 |
| F2 | 密钥初始化 | 已认证用户 | 首次使用时向 KGC 申请本人 SM9 私钥；私钥包经业务接口转发后保存在浏览器本地，不写入业务库 |
| F3 | 文档加密投递 | 已认证用户 | 选择文件与一至多位接收人，浏览器内完成加密后上传；支持加密备注 |
| F4 | 文档接收解密 | 已认证接收人 | 查看本人收件列表，下载密文分块并在浏览器内校验、解密、还原文件 |
| F5 | 换设备重签发 | 已认证用户 | 更换设备后再次申请由同一身份确定的私钥；恢复能力以 KGC 主密钥备份完好为前提 |
| F6 | 用户管理 | 管理员 | 创建用户（联动 KGC 身份登记）、启用/停用账号、调整角色；禁止修改自身 |
| F7 | 审计查询与校验 | 审计员 | 分页查询审计日志，一键校验哈希链完整性 |
| F8 | 安全事件监控 | 审计员 | 查看七类安全事件告警及其严重级别 |
| F9 | 签发记录查询 | 审计员 | 查询 KGC 私钥签发流水（首发/重签发） |

其中 F3 为核心用例，其基本流程为：用户登录后进入发送页，选择文件和一至多位接收人，可填写备注；浏览器生成一次性 SM4 文件密钥，按块加密文件与元数据（文件名、类型、备注），并按每位接收人身份封装密钥信封；随后初始化投递记录、逐块上传密文、提交完成。接收方在 F4 中执行逆过程。应用服务器在文件数据面只处理密文，但在密钥初始化控制面会短暂转发 KGC 返回的私钥包。

## 3.2 非功能需求

（1）安全性边界：**业务数据库与对象存储不得持久化文件明文、明文元数据、SM4 文件密钥和用户 SM9 私钥**。文件内容加解密在浏览器执行；用户私钥由 KGC 计算，经应用接口短暂转发后保存在浏览器 IndexedDB。应用服务器和 KGC 控制面被列为可信计算基，完全攻破应用服务器不属于当前方案已经消除的威胁。

（2）性能：算法层 SM4 加密吞吐不低于 10 MB/s，单次热态 SM9 密钥封装不超过 100 ms；包含分块与摘要的 50 MB 文件加密吞吐不低于 6 MB/s，下载、校验与解密吞吐不低于 5 MB/s；加解密通过后台线程反馈进度，避免长时间阻塞界面交互。

（3）可用性：加解密过程提供逐块进度反馈；换设备后无需人工备份私钥即可恢复；操作界面对非专业用户友好，密码学细节对用户透明。

（4）可移植与可部署：数据库支持 H2（开发）与 MySQL 8（生产）双环境；密文存储支持本地文件系统与 MinIO 对象存储切换；系统纯软件实现，不依赖专用密码硬件。

（5）合规性：密码算法选择采用 SM3、SM4 与 SM9 国家标准体系，关键操作保留审计记录。本文只完成算法示例与工程测试，不能替代密码产品检测、商用密码应用安全性评估或正式合规认证。

## 3.3 安全威胁分析

针对系统资产（文件明文、文件密钥、用户私钥、KGC 主私钥、审计日志、用户凭证），对主要威胁及对策分析如表 3.2 所示。

表 3.2 安全威胁与对策分析

| 威胁 | 攻击面 | 对策 |
|---|---|---|
| 传输窃听 | 浏览器与服务器链路 | 内容层端到端加密，链路仅传输密文（生产另叠加 HTTPS） |
| 存储侧泄露 | 数据库、对象存储、只读运维备份 | 盲存储：只持久化密文分块、加密元数据与密钥信封；存储侧无用户私钥 |
| 非接收人解密 | 持合法账号的内部人员 | DEK 按接收人身份 SM9 封装，非接收人无对应私钥；接口侧校验接收人资格 |
| 越权操作 | 普通用户调用管理/审计接口 | 方法级 RBAC（@PreAuthorize），401/403 统一拦截并记录安全事件 |
| 口令暴力破解 | 登录接口 | 失败计数锁定账号 + IP 限流，触发 BRUTE_FORCE_LOCK/IP_THROTTLED 事件 |
| 密文损坏或孤立篡改 | 存储或传输中的分块 | 上传与下载均比对 SM3；上传失配拒绝，下载发现存储摘要不一致时记录 CHUNK_TAMPER_DETECTED |
| 伪造身份骗取私钥 | KGC 签发接口 | 服务令牌鉴权 + 身份与登记记录一致性校验（IDENTITY_MISMATCH 拒绝） |
| 审计记录修改 | 具备数据库写权限的内部人员 | SM3 哈希链校验受保护字段与中间链路；外部锚点缺失使链尾或整表删除仍需额外防护 |
| 主密钥窃取 | KGC 服务器文件系统 | 主私钥经 PBKDF2+AES-256-GCM 加密落盘；生产部署必须移除开发默认口令并独立保管口令 |
| 资源滥用 | 超大分块耗尽存储 | 分块大小上限校验，超限拒绝并记录 OVERSIZED_CHUNK |
| 应用控制面失陷 | 应用服务器及其 KGC 服务令牌 | 当前不在已消除威胁内；生产应使用 mTLS、短期最小权限凭据、签发审批与异常签发监测 |

该分析表明，客户端内容加密可以降低数据库、对象存储与备份泄露的影响，但不能自动解决可信控制面被完全攻破、KGC 密钥托管、恶意服务器同时替换密文与摘要等问题。认证强度与口令管理参照 NIST 数字身份指南的原则[24]，应用接口安全控制结合 OWASP ASVS 的验证思路[25]；端点加密、认证授权、限流、密钥治理与审计需要协同设计。

## 3.4 本章小结

本章从三类主要角色出发梳理了九项功能需求，明确了“业务数据库与对象存储不持久化明文、文件密钥和用户身份私钥”的数据边界，并对十一类安全威胁与剩余风险给出对策映射。这些需求与威胁模型直接驱动第 4 章的总体架构、数据库与安全机制设计。
